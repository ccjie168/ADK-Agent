SLICE-290 凭据停用的跨租户校验 — 证据
====================================

日期: 2026-11-25
分支: slice-290-credential-disable-tenant
依据: SLICE-283 证据记录的 S-2（自定义角色获得 connectors.manage 后可跨租户停用凭据）

## 反例（先红）

    python -m pytest tests/test_console_credentials_cross_tenant.py -q

首次 2 failed：除跨租户用例外，admin 用例也失败——自定义 role store 里没有 admin 定义，
fail-closed 之后 admin 只得到 base 能力。补上 store 内的 admin 角色（能力取 CAPABILITIES_ALL）后：

    1 failed, 3 passed

失败项正是非 admin 跨租户停用：旧代码越过授权并**成功停用**，返回 200（断言 200 == 403 失败）。
其余三条（admin 跨租户、本租户、列表 403）在旧代码上通过，作为回归保护。

## 实现（后绿）

`src/adk_agent/console.py` 的 disable 在能力与配置检查之后、租户/凭据 id 校验之前增加：

    if tenant and tenant != caller.tenant and "admin" not in caller.roles:
        return 403 tenant_forbidden

`docs/contracts/console.md` 的 disable 一节补 403 规则与顺序。

    python -m pytest tests/test_console_credentials_cross_tenant.py \
        tests/test_console_credentials_tenant.py tests/test_console_credentials.py -q
    25 passed

## 实机验证（8040，admin，`--credentials-dir`）

    POST /api/credentials（租户 acme）-> register=201
    POST /api/credentials/crm/disable?tenant=acme -> admin-disable=200
    GET  /api/credentials?tenant=acme -> list=200

非 admin 的自定义角色路径由 TestClient + role store 覆盖（实机没有对应 IdP）。
