notes
-----
- The waiter process submitted through `PostgresApprovalInbox.request()` and
  blocked on polling. The console process listed the request over HTTP and
  recorded the decision. The waiter returned the same decision object. This is
  the cross-process path ADR-0017 targets.
- A second console pointed at a closed port returned 503
  `approval_unavailable` instead of an empty list or a 500.
- Review fix: DB prune originally opened the pool under one `asyncio.run` and
  closed it under a second. The pool is loop-affine, so the close could not
  succeed. Prune now runs and closes inside one coroutine.
- Review fix: the console `approvals` parameter uses
  `FileApprovalInbox | PostgresApprovalInbox | None` instead of `Any`, so the
  sync/async contract is visible to type checking. Handlers still await when
  `inspect.isawaitable` says so, because the union of the two return types is
  not statically narrowed to the async branch.
- Backend precedence is in one helper, `cli._approval_backend`: explicit flag
  beats environment, env-only conflict resolves to `APPROVAL_DATABASE_URL`,
  both explicit flags exit 1. The same helper serves console and prune with
  different flag names.
- The console closes a DB inbox pool after uvicorn returns, best effort, for the
  same loop-affinity reason as the audit query.
- Existing file-mode console and prune tests still pass; no existing assertion
  was changed. The old `test_cli_requires_dir` matches the substring
  "approval dir" in the new combined error message.
