三、实现要点

- `adapters/adk/models.py`：`BaseLlm`/`LlmRequest`/`LlmResponse` 类型导出，四个 provider
  构造器（`gemini_model`、`claude_llm`、`vertex_claude`、`litellm_model`）保留惰性导入，
  缺可选包时仍抛 `ImportError`。
- `adapters/adk/mcp_tools.py`：`stdio_params`、`http_params`、`mcp_toolset`。
  `timeout` 默认 60 秒与 ADK 的 `StdioConnectionParams` 签名一致（mypy 报错后改的）。
- `adapters/adk/tools.py`：`openapi_toolset`。
- 模型选择逻辑、key 注入方式、网关包装与策略审计都没动。
- 墙的基线 11 → 7；SLICE-317 的账本用例按用户已批准的「只增不减」模式改成
  `BASELINE <= 11 项旧集合`，当前 7 项由本切片用例精确固定。

六、限制

- 基线剩 7 项：`sandbox.*`（5 个）、`tools.enforcement`、`tools.guard`；3c 迁。
- `models/gateway_llm.py` 仍是 `BaseLlm` 子类并消费 ADK 的 `LlmRequest`/`LlmResponse`
  类型，只是 import 改走适配层；模型网关的协议本身没有平台化（不在本 ADR 范围）。
- 四个 provider 构造器只做转发，provider 的类名/参数语义随 ADK 版本变化，兼容演练的
  `model-providers` 尚未单独检查（见 3c 的升级手册）。
