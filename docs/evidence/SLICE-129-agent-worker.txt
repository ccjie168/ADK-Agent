二、实现

- sandbox/frames.py：4 字节大端长度加 JSON，32 MiB 上限，同步与 asyncio 两套读写。
- sandbox/agent.py：SandboxResult、AgentSandboxBackend 协议、注册校验（object() 抛 TypeError）。
- sandbox/agent_process.py：ProcessAgentSandbox 起子进程、写请求帧、并发读 stderr、墙钟超时后 kill，
  按 error 帧映射 SandboxViolation / SandboxCrashed，超时抛 SandboxTimeout。
- sandbox/agent_worker.py：读请求、设 RLIMIT（POSIX）、建事件循环、装网络守卫、清空环境，
  再走共享的 load_artifact_agent 与 ADK Runner 跑一轮，回 limits / final / error 帧。
  帧写 os.dup(1) 保存的句柄，fd 1 重定向到 stderr，工件打印不污染协议。
- registry/loader.py：抽出 load_artifact_agent，InProcessArtifactLoader 行为不变。
- sandbox/errors.py：新增 SandboxCrashed。
- 契约：docs/contracts/sandbox.md 与 README 索引。

三、实现中的发现

- 首次运行三个正常用例都报 SandboxViolation。原因在 Windows：asyncio 的事件循环创建时会用 socketpair，
  而守卫已把 connect 拦掉。改为先建循环、再装守卫、用 loop.run_until_complete 跑，守卫仍然在工件加载之前生效。
  这个顺序写进契约，POSIX 同样适用。
- 错误帧的 message 从类名扩成「类名: 短消息」，便于区分工件自身的异常与守卫拒绝，截断到 200 字符。

五、范围与已知缺口

- 本切片不注册后端，生产仍把 sandboxed 当作不可用；触发服务、控制台与模型出口中介在后续切片接入。
- 工件仍可读宿主文件系统；v1 不做命名空间，见 ADR-0024 第 9 条。

六、第一轮独立验证（HEAD 7ab2f57）与修复

验证结论 DO NOT MERGE，主要问题与处理：

1. [P0] memory_mb 直接传给 RLIMIT_AS，单位是字节，Linux 上所有正常工件崩溃。
   修复：乘 1024×1024；上报改为 getrlimit 读回值。WSL 上 sandbox 用例全部通过。
2. [P0] 协议错误路径先 await stderr 再回收，工件写畸形帧并保持存活可让父进程无限挂起。
   修复：先 kill 并 wait，再读 stderr；stderr 继续读并丢弃前 8 KiB 之后的内容；墙钟覆盖写请求与帧循环。
   新增 POSIX 回归 tests/sandbox/test_agent_process.py::test_malformed_frame_does_not_hang。
3. [P0/P1] 网络守卫只覆盖三个 Python 方法，UDP、子进程、AF_UNIX 与 _socket 可绕过。
   修复：严格模式额外拦截 AF_INET/AF_INET6/AF_UNIX 的 socket.socket 构造、_socket.socket 构造
   （模块属性替换为守卫子类）、os.system/os.popen/fork/exec*/spawn*/subprocess.Popen。
   残留：内省拿原始 C 类型或用 ctypes 调 libc 仍可绕过，写入契约与 ADR-0024 第 9 条一致。
   WSL 与 Windows 新增用例覆盖 UDP、AF_UNIX、_socket、subprocess。
4. [P1] 无一次性临时目录，cwd 进入 sys.path 可被投放模块。
   修复：父进程建临时目录作 cwd，运行后删除；改用 -I 启动。
5. [P1] 能力探针只查属性存在。
   修复：要求可调用且是协程函数；run=1 与同步 run 都被拒。
6. [P1] 失败分类按异常类，工件可伪造。
   修复：守卫记录它抛出的实例，worker 沿异常链按实例身份判定；伪造 SandboxViolation 归为 crash。
7. [P2] 非法 limits 帧值、输入静默截断、stderr 排空、3.10 超时类型、SandboxCrashed 未导出、错误信息含宿主路径。
   修复：非法 limits 抛 SandboxCrashed；去掉静默截断并在契约写明输入上限由调用方负责；stderr 读到 EOF、只留前 8 KiB；
   except asyncio.TimeoutError；sandbox/__init__ 导出 SandboxCrashed；契约写明 stderr 摘录可能含宿主路径且只给可信调用方。

九、第二轮独立验证（HEAD b052fab）

结论 MERGE，七项 must-fix 的原始场景全部关闭。Medium 残余项处理如下：

- `subprocess._fork_exec`、`_posixsubprocess.fork_exec`、`_winapi.CreateProcess`、`os.startfile` 纳入严格守卫；

十一、第三轮复核（HEAD 2f54c80）

结论 DO NOT MERGE：asyncio 的 `Process.wait()` 只在所有管道断开后唤醒。工件用 ctypes fork 一个持有
stdout/stderr 的后代并保持存活时，子进程已被杀但 `_reap` 的第二次 `wait()` 仍会挂住，wall + 10 秒的
硬上界不成立（验证代理用 ctypes fork 复现，wall=6 时 25 秒仍未返回）。

修复：
- POSIX 上 worker 以独立会话启动（`start_new_session=True`）。
- 回收用 `os.killpg(pid, SIGKILL)` 杀掉整个进程组，再 `wait`；`wait()` 与 stderr 收尾各带 5 秒上限，
  即使后代 setsid 逃逸也不会拖住父进程。
- 新增 POSIX 回归 `test_descendant_holding_pipes_does_not_hang`（ctypes fork 持管道，断言有界结束）
  与 `test_posixsubprocess_fork_exec_is_denied`。

验证：
- WSL Ubuntu 24.04 `pytest tests/sandbox -q`：48 passed。
- Windows `scripts/check.py --full`：1394 passed, 86 skipped，9 步全 PASS。

十二、第四轮复核（HEAD a73975f）

结论 DO NOT MERGE，但不是代码缺陷：进程组回收有效，逃出会话的后代也让 run() 有界返回；
问题是契约写 wall + 10 秒，实测最坏 teardown 是 15 秒（`_reap` 两次 5 秒加 stderr 5 秒），wall=6 时总耗时 18.47 秒。

处理：
- 契约改为 wall + 15 秒加启动开销，并说明两次 wait 与 stderr 的预算来源。
- 新增 POSIX 回归 `test_escaped_descendant_is_still_bounded`：ctypes fork 的后代先 `setsid()` 逃出进程组，
  再持管道睡 60 秒；断言 run() 在 30 秒内以 SandboxCrashed 结束。修复前会挂到后代退出（60 秒），因此该用例有判别力。
  WSL 上实测 21.5 秒通过。
