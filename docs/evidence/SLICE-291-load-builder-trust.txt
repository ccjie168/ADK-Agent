红灯原因是新参数与新标志在 master 上都不存在：`load_agent`/`build_console_app` 没有
`builder_keys`（TypeError），五个命令的解析器没有 `--builder-keys`（argparse exit 2）。
master 本来就不设防，所以「带信任集能载入」在旧代码上也无从表达，17 条全部失败。

2) 触发服务用例（新增部分）：

    $ python -m pytest \
        tests/test_triggers_service.py::test_fire_refuses_in_process_without_builder_trust \
        tests/test_triggers_service.py::test_fire_refuses_an_untrusted_builder_signature \
        tests/test_triggers_service.py::test_fire_verifies_the_builder_signature \
        tests/test_cli_triggers_service.py::test_serve_triggers_passes_the_builder_keys \

    5 failed in 2.25s

build_triggers_app 在 master 上没有 builder_keys 参数，serve-triggers 解析器没有
--builder-keys，两个 CLI 用例分别以 SystemExit 2 与 KeyError 结束。

3) 首轮独立验证（PR #330）指出 serve-triggers 仍能执行未验签的 in_process 记录，
本切片已补上并在上面 2) 记录了红灯；同一轮还指出 sandboxed 用例只在「传入了信任集」时
断言未被调用、以及 --builder-keys 文件标志与 serve-many/serve-a2a 接线没被覆盖，
均已改：sandboxed 用例遍历 None 与桩信任集两种输入；serve 用例改用 --builder-keys 文件，
新增 serve-many、serve-a2a 与五个命令的 --help 覆盖。

二、行为证明：master 真的执行了没有构建签名的 in_process 工件

探针脚本在临时目录手工构造一条文件注册表记录：发布签名合法（publisher-1），
builder_signature / builder_key_id 为空，execution_tier=in_process。

master 源（PYTHONPATH 指向 git archive 出来的 master src）：

    $ PYTHONPATH=<temp>/master/src python probe.py <temp>/master-run
    builders: parameter absent (load_agent() got an unexpected keyword argument 'builder_keys')
    loaded: bot
