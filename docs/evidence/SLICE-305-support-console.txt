三、实机：控制台里点批准

1. 用控制台的审批目录与独立审计文件启动演示：

       $ python scripts/prove_support_demo.py --interactive --wait-seconds 90 \
           --approvals-dir C:/Users/Jie/.adk/state/approvals \
           --audit-file C:/Users/Jie/.adk/state/support-demo-audit.jsonl
       PASS approval requested
       WAITING approval b19aff15170f4255b3bd9a81446c7f5d in C:\Users\Jie\.adk\state\approvals

2. 控制台 `GET /api/approvals` 同一条请求可见（step `ticket`、理由「创建工单会通知客户」）。
3. 用控制台 `POST /api/approvals/<id>`（即页面上的批准按钮）决定：

       {"request_id":"b19aff15...","approved":true,"approver":"console_user", ...}

4. 演示继续并输出：

       PASS plan answered
       PASS ticket created t-1
       PASS ticket is open
       PASS wecom notified
       PASS audit verified (4 records)
       ALL PASS

六、限制

- 审批页可见是因为两边用同一个 `--approval-dir`；审计页要可见，控制台需以
  `--audit-file` 指向同一文件启动（当前 8000 的控制台没有该参数，所以演示审计写在
  `support-demo-audit.jsonl`，页面看不到）。
- 交互模式给计划加了 `wait-seconds + 60` 的截止时间，超时残留的审批请求带 `expires_at`，
  控制台会按过期处理，不会留下“永不超时的待批”。
- 登记脚本可重复运行：已存在的凭据绑定跳过，连接器按既有 store 语义幂等。
- 连接器“可见”不等于“可执行”：工具网关仍按连接器与授权执行，本切片只做登记。
