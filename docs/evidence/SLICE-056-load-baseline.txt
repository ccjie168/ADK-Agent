== baseline reading ==
Machine: Windows 11 Pro, Python 3.14, venv. Absolute numbers are machine-specific; compare future runs to these.
- In-memory quota is CPU-bound on the event loop (0.001 ms median). It says nothing about multi-replica cost.
- Postgres quota serializes on the per-tenant advisory lock, and the pool is capped at max_size=5. With 32
  workers the median reserve is 215 ms and throughput 159/s. Denied attempts queue behind the same lock,
  so a tenant at its limit pays the same cost as an allowed one. This is the current capacity ceiling.
- Concurrency cap holds exactly: peak_active never exceeded max_concurrent. With holds shorter than reserve
  latency the cap is underused (peak 2 of 5), so a cap of N needs each run to hold longer than a reserve
  round trip to actually reach N.
- Audit append is fsync-bound: about 340 records/s and a 3 ms median per record on this disk, unchanged by
  rotation. Sustained ingest above that rate will back up the writer.
