notes
-----
- The console writes the three management audit events under the caller's
  tenant (`local` for the static token), with the peer id or `<peer>/<agent>`
  as the target. CLI writes go straight to the store and do not audit, matching
  the existing `connectors` and `lifecycle` commands; the contract says so.
- The A2A server reads peers per request, so disabling through the console took
  effect on the next card request without a restart.
- `peer.call` denials and `agent.run` events already render in `/api/audit`
  because the view does not filter actions; `test_peer_call_in_audit_view`
  pins that.
- A non-admin request for another tenant's list now returns `tenant_forbidden`
  instead of silently returning their own rows.
