SLICE-158 控制台凭据列表的非法租户参数
日期: 2026-11-19
依据: PROGRESS 缺口清单第 8 条
基线: 363e0de

一、实现

- `GET /api/credentials` 在跨租户检查之后、能力检查之前用有界模式
  `^[A-Za-z0-9][A-Za-z0-9._+-]{0,127}$` 校验 `tenant`，非法、空或超长返回 400 `unsafe_tenant`，
  不再把输入传给 `safe_join`；128 字符的合法租户仍可读取。
- `docs/contracts/console.md` 写明检查与顺序。

二、绿态

$ pytest tests/test_console_credentials.py -q
14 passed

$ pytest -q（Windows）

$ python scripts/check.py --full
ALL PASS

三、红态

基线 363e0de 把 `tenant=bad/name` 交给 `safe_join`，抛 `UnsafePath`（控制台 500）；
129 字符的安全字符 tenant 由于旧模式没有长度上界，同样落到 `safe_join` 返回 500；
空 `tenant` 回退到调用方租户并返回 200。新用例断言 400 时全部失败。

四、范围与已知缺口

- 凭据读写接口里 `credential_id` 路径参数的同类校验不在本切片（disable 已做）。
- 跨租户 admin 写入的审计归属、Postgres 并发停用重复审计与解密失败审计的 invocation
  归因仍在缺口清单。
