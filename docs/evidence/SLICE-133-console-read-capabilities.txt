依据: ADR-0022 第 1、8 条
基线: 48d9024

二、实现

- console.py 新增 `_forbidden_if_missing(caller, capability)`，统一返回 403 `{"error": "forbidden"}`。
- 下列读接口在 `_principal_for` 与租户参数检查之后、任何存储读取之前检查能力：
  - `GET /api/audit` -> `audit.read`
  - `GET /api/policy` -> `policy.read`
  - `GET /api/registry` 与 `GET /api/registry/{tenant}/{id}/{version}/eval` -> `registry.read`
  - `GET /api/tools` -> `tools.read`
  - `GET /api/tool-grants` 与 `/usage` -> `grants.read`
  - `GET /api/connectors`、`/api/connector-requests`、`/api/credentials` -> `connectors.read`
  - `GET /api/peers` 与 `/api/remote-agents` -> `peers.read`
- 聊天面板的 Recent audit 区块包进 `data-capability="audit.read"`，`loadAudit()` 在没有该能力时不请求。
- 契约：`docs/contracts/console.md` 每个读接口写明能力与 403、租户参数先于能力检查；
  新增 `GET /api/policy` 一节，并说明 `PUT /api/policy` 仍走 `policy.update` 的 RBAC。
- 测试主体调整（断言不变，只换主体角色以匹配新授权模型）：
  - `test_console_peers.py::test_tenant_visibility`：viewer -> operator
  - `test_console_remote_agents.py`：读断言所在客户端 viewer -> operator
  - `test_console_oidc.py`：own registry 读与 audit 读 guest -> ops
  - `test_console_shared_audit.py::test_console_scopes_tenant`：主体补 operator 角色
  - `test_tool_grant_usage.py::test_usage_tenant_scope`：viewer -> operator
  - `test_policy_api.py`：被拒写后先直接读策略文件再构造 ops 客户端（构造会重写策略文件），
    审计改用 ListAuditSink 断言；新增断言覆盖被拒的 policy.update 写 denied 审计
  - `test_console_tools.py` 新增 `test_operator_lacks_tools_capability`，固定 operator 无 `tools.read`

四、范围与已知缺口

- 写路径未改：注册表 load/unload、连接器注册/停用/检查、连接器申请提交与决定、
  凭据注册/停用、对端与远程 agent 写操作、tool-grants 提交与决定仍按 admin 或既有 RBAC。
- 基础能力接口（runs、plans、traces、sessions、chat）对所有登录主体开放，符合 ADR-0022 的初始映射。
- 界面与服务端在 `grants.decide`、`connectors.manage` 上仍不一致：界面给 operator 显示决定按钮，
  服务端只允许 admin；写路径对齐另行切片。
- 存储未配置的 404 与 `status` 非法的 400 先于能力检查，只暴露配置与参数是否合法。
- `GET /api/registry` 用 `registry.read` 同时返回远端目录条目，`GET /api/remote-agents` 需要
  `peers.read`，发布者能经注册表看到远端元数据，与 Registry 面板可见范围一致。
- Registry 面板的 Refresh selected 对远端记录调用 `POST /api/remote-agents/{id}/refresh`，
  服务端仅 admin；发布者能看到按钮并得到 403，属既有界面/写路径不一致，另行切片。
