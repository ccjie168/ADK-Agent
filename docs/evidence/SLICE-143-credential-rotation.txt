SLICE-143 凭据轮换：数据密钥重新包裹
日期: 2026-11-18
依据: ADR-0025 第 6 条与第 1 条（会话确认增加 rewrap）
基线: fa56229

一、实现

- `KeyBackend` 端口增加 `rewrap(wrapped, aad)`；`LocalKeyBackend` 用旧 key id 解开数据密钥，
  用当前 KEK 与新的包裹 nonce 重新包裹，凭据值的密文与 nonce 原样保留；key id 已是当前值时
  仍校验 AAD，然后原样返回。
- `CredentialStore` 端口增加 `replace_wrapped(tenant, credential_id, wrapped_secret, secret_key_id)`：
  只更新密文与 key id。文件存储在 `<id>.json.lock` 上取 OS 文件锁（Windows `msvcrt.locking`、
  POSIX `flock`）后先读后写，跨进程串行；Postgres 用 `jsonb_set` 只改这两个键，`disable` 也只改
  `enabled`；并发的 `disable` 与 `description` 修改不会被覆盖；记录不存在抛 `CredentialNotFound`。
- `credentials rewrap --tenant T [--dry-run]` 逐条换到当前 KEK，输出
  `{tenant, rewrapped, skipped, dry_run}`；缺 `ADK_SECRET_KEKS` 退出 1。
- 标识符长度上限 128：`CredentialBinding` 的 `_SAFE_NAME`/`_SEGMENT` 与路由校验同步收紧，
  超长 id 由 500 改为 400。
- ADR-0025 第 1 条与确认记录、`credentials.md`、`cli.md` 已同步。

四、范围与已知缺口

- 轮换仍要求保留旧 key id；删除旧 KEK 后旧记录按 fail-closed 处理。
- ADR-0025 第 8 条的 `credential.decrypt_failed` 审计仍未做。
- KMS 后端的 `rewrap` 实现随 KMS 端口一并做。

五、第一轮独立验证

结论 DO NOT MERGE。密码学通过（重新包裹不改值密文、AAD 双路径校验、旧 KEK 兼容），
但新增的覆盖写有丢失更新：轮换循环从 `list()` 取快照后用整条记录覆盖，期间并发 `disable`
会被写回 `enabled=true`，等于把刚吊销的凭据重新启用。处理：

1. 高：`replace` 改为 `replace_wrapped`，只合并 `wrapped_secret` 与 `secret_key_id`；
   文件存储在锁内先读后写，Postgres 用 `jsonb_set` 只改这两个键；补并发停用用例。
2. 低：跳过条件同时检查记录字段与实际 payload 的 `key_id`，避免元数据与密文不一致时漏迁移。
3. 低：`rewrap` 校验 `nonce`/`ciphertext` 类型，并把 `cryptography` 的 `ValueError` 一并映射为
   `KeyBackendError`；补 payload 形状用例。
4. 低：`credentials.md` 的语法与 `cli.md` 的标题补 128 长度上限与 `rewrap` 子命令。
5. 低：补 Postgres `replace_wrapped` 实库用例（无 TEST_POSTGRES_URL 时跳过）与停用路由的超长 id 用例。

六、第二轮独立验证

结论 DO NOT MERGE。Postgres 侧的丢失更新已关闭，但文件存储的互斥只在单实例内
（`threading.Lock`），`credentials rewrap` 与服务进程各建一个 store，跨进程仍会把并发
`disable` 写回成启用。处理：

1. 高：文件存储在记录旁建 `<id>.json.lock`，读改写期间持有 OS 文件锁
   （Windows `msvcrt.locking`、POSIX `flock`）；补锁阻塞与“先取锁后读”的确定性用例。
2. 中：原“并发停用”用例是顺序执行，补跨线程锁用例证明互斥生效。
3. 低：Postgres `disable` 改为 `jsonb_set(definition, '{enabled}', 'false')`，不再整条覆盖，
   不会把并发 rewrap 的结果写回旧密文。
4. 低：`rewrap` 校验值 `nonce`/`ciphertext` 的 base64 形状与 nonce 长度；非 Mapping 输入拒绝。
5. 低：文件存储的 `_NAME` 同步 128 长度上限。
