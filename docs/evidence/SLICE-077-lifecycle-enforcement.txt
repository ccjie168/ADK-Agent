live, service, CLI and console in separate processes
----------------------------------------------------
Database `adk_live5` already had acme/support-bot@1.0.0 retired by SLICE-076.
Published 2.0.0 over HTTP and deprecated it with the new command:

$ adk-agent lifecycle set --registry-url http://127.0.0.1:8810 \
    --tenant acme --id support-bot --version 2.0.0 \
    --status deprecated --reason "superseded soon"
acme/support-bot@2.0.0 status=deprecated
exit=0

Console started with `--agent-ref acme/support-bot@1.0.0` (retired):
  registry load failed: acme/support-bot@1.0.0 is retired
  exit=1

Console with probe-only agents, then over HTTP:
  GET /api/registry?tenant=acme -> [(1.0.0, retired), (2.0.0, deprecated)]
  POST /api/registry/load 1.0.0 -> 409 {'error': 'version_retired'}
  POST /api/registry/load 2.0.0 -> 409 {'error': 'artifact_missing'}
    (lifecycle allowed the deprecated version; it has no artifact in this seed)

Screenshot: docs/evidence/ui/SLICE-077-lifecycle.png shows the registry table
with retired and deprecated lifecycle badges.

notes
-----
- `HttpAgentLifecycleStore` adapts the registry client to the store port,
  because `HttpAgentRegistry.get` is the record lookup and cannot also be the
  lifecycle get.
- Loading a version now checks lifecycle before touching artifact bytes, so a
  retired record fails even when its artifact is missing.
- The CLI verifies the version exists in file mode; the service enforces it in
  HTTP mode.
