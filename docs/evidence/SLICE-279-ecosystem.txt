## 独立验证反馈修正

首轮验证判 PASS，提出 2 个 S 与 2 个 N，已处理：

1. **S-1**：`kind=mcp` 连接器产出的工具在 `/api/tools` 里 `source` 是 `connector`，原来的
   「MCP 工具」卡与筛选只认 `source=mcp`，登记后仍显示 0。现在按「`source=mcp` 或
   `tool_id` 属于某个 `kind=mcp` 连接器」统计与筛选。
2. **S-2**：MCP 服务片段没有先设置令牌环境变量，原样复制会启动失败。现在命令带
   `ADK_MCP_TOKEN=your-token` 前缀，hint 说明先导出；A2A 拆成「登记」与「授权」两张卡，
   补上 `peers grant` 命令。
3. **N-1**：测试补断言 `canTools && toolsReady` 等绑定与 `mcpConnectorIds`/`isMcpTool`。
4. **N-2**：样式新增块前的多余空行已清理。

## 第二轮验证反馈修正

第二轮验证判 PASS，提出 2 个边界 B 与 2 个 N，已处理：

1. **B-1（id 碰撞）**：`isMcpTool` 现在要求 `source === "connector"` 才按连接器 id 匹配，
   并且只收集 `enabled` 的 `kind=mcp` 连接器；静态 function 工具与已禁用连接器不会再被误算。
2. **B-2（无 connectors.read 的角色）**：MCP 计数卡要求 `toolsReady && connectorsReady`，
   拿不到连接器时显示「—」，不再把「看不见连接器」显示成 0。
3. **N-1**：spec 与证据里的「三张接入引导」改为四张。
4. **N-2**：命令补上存储参数——连接器 `--connectors-dir ./connectors`，对端
   `--peer-dir ./peers`，复制即可运行。
5. **N-3**：S-1 的行为仍以源码断言锁定（`source === "connector" && mcpConnectorIds...`）；
   实机没有连接器 store，无法走完整的「登记 mcp 连接器 → 工具变 MCP」链路，作为已知证据缺口记下。
