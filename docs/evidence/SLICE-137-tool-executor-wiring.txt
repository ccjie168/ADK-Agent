二、实现

- 复用 `core.context` 的 `current_invocation()`：`AgentRuntime._run` 与 `AuditedRunner` 都会设置，控制台与 MCP/A2A 共用同一个 contextvar。
- 新增 `tools/client.py`：`ToolGatewayClient.invoke(invocation, tool_id, args, grants)`，
  200 返回 `ToolResponse.output`，403 -> `ToolDenied`，5xx/非 200/网络错误 -> `ToolGatewayError`。
- 新增 `tools/executor.py`：`gateway_executor(client)` 返回
  `async (manifest, tool_id, args, invocation)`；无 invocation 抛 `tool_principal_unavailable`，
  网关拒绝映射 `tool_denied`，网关故障映射 `tool_gateway_unavailable`，非映射输出包装成 `{"output": ...}`。
- `sandbox/agent.py`、`agent_process.py`、`proxy.py`：`run` 增加 `invocation` 关键字并传给执行器；
  执行器的 `SandboxToolError` 按 code 回帧。
- `cli.py`：`--tool-gateway-url` / `--tool-gateway-token-env` 加到 console、serve、serve-many、serve-a2a；
  `--agent-sandbox` 且给了网关 URL 时构造带执行器的 `ProcessAgentSandbox`，工具授权记录因此可加载。
- 契约：`sandbox.md` 的执行器签名、`cli.md` 的新 flag、新增 `tool_gateway.md`。

四、范围与已知缺口

- 触发路径仍不接执行器，声明工具授权的 `sandboxed` 触发继续拒绝。
- 审批由网关既有 `approval_required` 处理，本切片不新增审批交互。
- 网关 token 只从环境变量读取，不进入子进程。
- `serve-a2a` 的 `--tool-gateway-url` 只在该命令使用 `--agent-sandbox` 时生效。

五、第一轮独立验证（PR 48 首版）

结论 DO NOT MERGE。关键问题：

1. 高：首版新增了第二个 `runtime/context.py`，只有 `AgentRuntime` 写它，而 serve/serve-many/serve-a2a
   走 `AuditedRunner`，写的是既有的 `core.context`，因此这三个命令的工具调用必然 `tool_principal_unavailable`。
   已删除新模块，代理改读 `core.context`，并把回归用例改为 `AuditedRunner -> SandboxAgent -> 执行器` 的端到端形态。
2. 测试缺口：补执行器错误码穿透到子进程的用例、`ToolGatewayError -> tool_gateway_unavailable` 用例，
   以及客户端 302 与无 token 的用例。
3. 证据计数：定向实际 27 passed，红态 2 failed / 15 passed 加 2 个 collection error，已改正。
4. 契约：`ToolGatewayClient.invoke` 返回值、`current_invocation` 来源、`run(invocation=...)`、
   `SandboxToolError` 会回 code 与 message、CLI 默认无执行器的表述均已改正。
5. 客户端显式 `follow_redirects=False` 与 `trust_env=False`；缺 token 时 CLI 在 stderr 告警。
