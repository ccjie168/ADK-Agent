== live: real uvicorn console, slow SSE client ==
A console app built with build_console_app(sse_queue_size=16), served by uvicorn on an ephemeral
port. A patched Runner emits 5000 tool calls plus a final text event, so the run produces 5003
progress events. The httpx client sleeps 20 ms per received chunk.

{"emitted_events": 5000, "queue_size": 16, "read_delay_s": 0.02,
 "progress_received": 1199,
 "done": {"reply": "final answer", "dropped": 3804, ...},
 "elapsed_s": 37.504}
exit=0   (1199 + 3804 = 5003; terminal event carried the reply)

Inference, not measured: the previous unbounded queue would have held all 5003 events until the
client drained them. The old build was not run again.

== reading ==
- Drops depend on how far the producer outruns the client, not on total run length. A burst of N
  events against a buffer of B keeps the newest B and drops N - B. The run never blocks on the UI.
- The queue bound is exact: peak_depth is queue_size + 1 because the terminal event sits on top.
- A slow consumer sees only the newest B events and a queue wait of seconds at 1 ms per event
  (p50 1.95 s, p99 3.9 s). The dropped count on the terminal event tells the UI how much it missed.
- The 20 ms-per-chunk live client received 1199 events instead of 16 because uvicorn drains the
  generator into its socket buffer whenever the client reads a chunk, so the buffer only fills while
  the socket is blocked. The bound held, and the terminal event always arrived.
