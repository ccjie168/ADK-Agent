notes
-----
- The card fetch sends the resolved `secret://` credential as a Bearer header and
  never stores or logs the raw token.
- A changed card does not overwrite the approved digest. `card_digest` stays at
  the last approval, `observed_digest` records the new bytes, and the status
  flips to `changed`. Only a re-registration approves the new digest.
- An unreachable refresh keeps both digests and only updates `checked_at`.
- Review hardening added a 409 `remote_agent_tenant_immutable`: re-registering an
  existing id under a different tenant is rejected before the card fetch.
- The Postgres upsert reads plain SQL literals instead of f-strings, which keeps
  bandit B608 quiet without a suppression.
