SLICE-186 模型别名路由器与降级
日期: 2026-11-20
依据: ADR-0033（Accepted 2026-11-19）决定 2/3 / slice 2
基线: b40222f

一、实现

- `models/routing.py` 新增 `resolve_candidates(policy, alias, data_classes)`：按 alias 取有序候选，
  过滤掉不在 `provider_allowlist` 的 provider，以及 `allowed_data_classes` 非空且不包含全部请求数据分类的
  候选；未知 alias 或无放行候选抛 `ModelDenied`。
- `PolicyModelGateway.complete` 增加 `alias`/`data_classes`：给 alias 时按序尝试候选，主候选抛错时降级到
  下一候选，全部失败抛 `ModelUnavailable`；策略拒绝（`ModelDenied`）不降级。原单次调用体抽出为
  `_complete_once`，不给 alias 时行为不变。
- `routing.py` 从 `.gateway` 导入 `ModelDenied`；网关在函数内延迟导入 `resolve_candidates` 以避免循环导入。
- 新增 `tests/models/test_model_router.py` 九个测试（含验证代理指出的「策略拒绝不降级」用例）。

四、范围与已知缺口

- 预算执行（slice 3）。
- 审计字段扩展：alias、实际模型、降级次数（slice 4）。
- 网关 HTTP 请求体按 alias 调用（后续接线）；当前 alias 路由是进程内网关能力。
- 降级只发生在同一 alias 的已放行候选之间；每次尝试仍完整经过 `check_provider` 硬门与审计。
