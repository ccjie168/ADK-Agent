## 实现（后绿）

- console.py：`build_console_app`/`run_console` 新增 `role_store`；新增闭包 `_caps_for(caller)`：
  无 store 时走 `_capabilities_for`（与改动前逐项一致），有 store 时按 `caller.roles` 逐个查定义取并集，
  未定义角色贡献空集、并集为空回落 `CAPABILITIES_BASE`，`RoleStoreError` 时记日志并返回基础能力（fail-closed）。
  `_forbidden_if_missing` 改为 async 闭包，44 处调用加 `await`；`/api/me`、`/api/overview` 与审批三处
  直连判断改用 `await _caps_for(caller)`；删除已被遮蔽的模块级旧实现。
- cli.py：`--role-store-dir` / `--role-store-db`（env `ROLE_DATABASE_URL`），互斥与 env 冲突均退出 2；
  配置 store 时启动用 `seed_builtin_roles()` 幂等写入，空 store 上 admin 仍可用。
- docs/contracts/console.md：补「能力来源 / fail-closed / 内置角色即默认种子」三条。

## 语义说明

角色定义是「该角色的完整能力集合」：store 中只写 `tools.read` 的自定义角色不会自动附带基础能力，
需要运维在定义里显式写入。内置种子沿用现有三档（每个都含基础能力），因此不配置 store 或使用种子时
行为与改动前一致（`test_capabilities_unchanged_without_store`、`test_seed_builtin_roles_keeps_admin_working`）。
