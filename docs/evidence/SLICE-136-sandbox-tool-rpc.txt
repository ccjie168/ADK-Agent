SLICE-136 沙箱工具调用中介协议
日期: 2026-11-18
依据: ADR-0024 第 3 条
基线: 8f35fcb

一、红态（实现前）

把 `src/` 换回基线 8f35fcb 后：

$ pytest tests/sandbox/test_agent_tool_rpc.py -q
ERROR tests/sandbox/test_agent_tool_rpc.py
E   ImportError: cannot import name 'SandboxToolError' from 'adk_agent.sandbox.agent'

$ pytest tests/test_registry_startup.py tests/test_triggers_service.py -q
2 failed, 38 passed

失败的是 test_loader_allows_tool_grants_with_executor（旧加载器一律拒绝工具授权）与
test_sandboxed_trigger_uses_the_backend（旧 `run` 不接收 manifest，records 为 None）。
新增 7 个用例在基线全部失败（5 个 tool RPC 用例 + 1 个加载器用例 + 1 个触发断言）。

二、实现

- `sandbox/agent.py`：`AgentSandboxBackend.run` 增加关键字 `manifest`；新增 `SandboxToolError(code, message)`，
  消息带 code。
- `sandbox/agent_channel.py`：`SandboxChannel.call_tool` 发 `tool` 帧，参数先做 JSON 校验；
  新增 `install_tool_proxy` 给 agent 树装 `before_tool_callback`，工具调用一律回到父进程。
- `sandbox/agent_worker.py`：加载工件后安装工具代理。
- `sandbox/agent_process.py`：`AgentSandboxLimits.max_tool_calls`（默认 100）；`ProcessAgentSandbox(tools=...)`
  与 `supports_tools`；`run(..., manifest=...)`；父进程按 frame 顺序做格式、上限、授权、执行器判断，
  执行器签名 `async (manifest, tool_id, args) -> Mapping`。
- `sandbox/proxy.py`：代理保存 manifest 并在每次运行传入。
- `registry/loader.py`：只有后端 `supports_tools` 时才允许带工具授权的 `sandboxed` 记录，否则维持
  `SandboxToolsUnavailable`。
- `triggers_service.py`：两次 `run` 调用传入发布 manifest。
- 契约：`sandbox.md` 新增工具中介帧一节；`console.md`、`cli.md`、`trigger_service.md` 同步执行器条件。

四、范围与已知缺口

- 工具执行器本身未实现：CLI 构造的 `ProcessAgentSandbox` 没有 `tools`，因此声明工具授权的
  `sandboxed` 记录仍被拒绝；触发路径同样只传 manifest、不执行工具。
- 接入片负责用工具网关/连接器实现执行器，并补审批状态与 `tool.call` 审计。
- 工具结果大小与脱敏细则未定。
- 沙箱内本地函数工具仍不执行；只有父进程授权的工具可调用。
