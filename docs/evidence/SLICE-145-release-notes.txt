五、第一轮独立验证

结论 DO NOT MERGE。发布说明里有两处事实错误（全量数字仍是 1566；把明文写入路径写成只有控制面），
另有升级与残余清单的措辞不精确。处理：

1. 高：全量数字改为 1569。
2. 高：明文写入路径改为“控制面 `/v1/credentials` 或 CLI `credentials register --secret-stdin`”。
3. 中：`demo_seed.py` 改为“只带演示发布签名、没有平台构建签名”，PROGRESS 同步。
4. 中：轮换删除旧 key 的判据改为“所有带密文记录的 `secret_key_id` 都是新 key id”，说明无密文记录计入 `skipped`。
5. 中：128 字符超长记录写明没有改名命令，需停用后按新 id 重新注册，且只影响打 tag 前的内部记录。
6. 低：守卫测试的版本正则限定在 `[project]` 表；章节改为整行精确匹配；占位检查改为大小写不敏感。
7. 低：沙箱残余改引 `docs/contracts/sandbox.md`，总体取舍仍指向 ADR-0024 第 9 条。
8. 低：CI 全绿改成“打 tag 前确认”，不在说明里预判尚未完成的检查。

六、第二轮独立验证

结论 DO NOT MERGE。超长凭据记录的处置说明不可执行，另发现文件存储对 124-128 字符 id 的真实边界
问题。处理：

1. 中：删除“停用后重新注册”的说法。超长记录在模型校验层就被拒绝，停用与重新注册都无法清理它；
   改为“备份后手动删除旧状态（文件后端删 `<tenant>/<id>.json`，Postgres 删行），再按新 id 注册；
   租户超长时换新租户”。
2. 中：文件存储的 `_path` 把 `.json` 后缀一起套 128 字符上限，124-128 字符的 id 通过模型校验
   却在落盘时抛 `UnsafePath`。改为先按 id 校验并拼路径，再追加固定后缀；补 128 字符 id 的
   存取用例。
3. 低：88 skipped 的说明补上 POSIX-only 沙箱用例。
4. 低：`rewrap` 示例补存储选择参数，并说明 `skipped` 同时包含无密文与已在当前 key id 的记录。
5. 低：PROGRESS 第 5 条关于工具调用仍被拒绝的陈旧描述已更新。
6. 低：证据里 `demo_seed` 的旧措辞已同步。
