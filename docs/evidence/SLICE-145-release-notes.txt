SLICE-145 v0.1.0 发布说明
日期: 2026-11-18
依据: 会话确认“先发布说明，再打 tag”
基线: dadd75c

一、实现

- 新增 `docs/releases/v0.1.0.md`：包含内容、安装、升级说明、已知缺口、发布验证与后续方向。
- 升级说明覆盖凭据迁移（128 字符上限、引用首段必须等于记录租户）、轮换步骤与 `publish` 的
  `in_process` 限制。
- 已知缺口与 PROGRESS 对齐：KMS、控制台明文写入、`credential.decrypt_failed` 审计、
  构建签名与 manifest 绑定、跨租户审计链、并发停用审计、demo_seed 未签名工件、Windows 锁重试、
  沙箱残余风险。
- 新增 `tests/test_release_notes.py`：发布说明必须与 `pyproject.toml` 的版本一致、章节齐全、
  没有 `TODO`/`TBD` 占位。

二、绿态

$ pytest tests/test_release_notes.py tests/test_install_guide.py -q
9 passed

$ pytest -q（Windows）
1569 passed, 88 skipped

$ python scripts/check.py --full
ALL PASS

三、红态

先加 `test_release_notes.py` 而不加 `docs/releases/v0.1.0.md`，第一个用例失败；
版本升级而不加说明文件同样失败。

四、范围与已知缺口

- 打 tag、GitHub Release 与镜像推送在本切片合并后单独执行；镜像只在本地构建验证。
- 没有英文版发布说明。

五、第一轮独立验证

结论 DO NOT MERGE。发布说明里有两处事实错误（全量数字仍是 1566；把明文写入路径写成只有控制面），
另有升级与残余清单的措辞不精确。处理：

1. 高：全量数字改为 1569。
2. 高：明文写入路径改为“控制面 `/v1/credentials` 或 CLI `credentials register --secret-stdin`”。
3. 中：`demo_seed.py` 改为“只带演示发布签名、没有平台构建签名”，PROGRESS 同步。
4. 中：轮换删除旧 key 的判据改为“所有带密文记录的 `secret_key_id` 都是新 key id”，说明无密文记录计入 `skipped`。
5. 中：128 字符超长记录写明没有改名命令，需停用后按新 id 重新注册，且只影响打 tag 前的内部记录。
6. 低：守卫测试的版本正则限定在 `[project]` 表；章节改为整行精确匹配；占位检查改为大小写不敏感。
7. 低：沙箱残余改引 `docs/contracts/sandbox.md`，总体取舍仍指向 ADR-0024 第 9 条。
8. 低：CI 全绿改成“打 tag 前确认”，不在说明里预判尚未完成的检查。
