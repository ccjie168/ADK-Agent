live, real Postgres and a service with an audit file
----------------------------------------------------
Fresh database `adk_live5`; service on 8809 with `--audit-file`.

  GET  .../lifecycle -> 200 {'status': 'published', 'changed_at': None, ...}
  PUT  deprecated    -> 200 changed_by=registry_operator reason=superseded
  GET  /v1/agents    -> record carries the same lifecycle object
  PUT  retired       -> 200 changed_at moved, reason=bad build
  PUT  published     -> 409 {'error': 'invalid_transition'}
  PUT  retired again -> 200 with the original changed_at (idempotent)

Audit file: two `agent.lifecycle` events, target `acme/support-bot@1.0.0`,
status ok, tenant acme. The idempotent call wrote no event.

notes
-----
- `FileAgentRegistry.list` now skips `.lifecycle.json` so the file store can
  live inside the demo registry tree.
- `HttpAgentRegistry` drops the service-layer `lifecycle` field before parsing
  `PublishedAgent`, whose model forbids extra fields.
- Audit is written only when the status actually changes.
- Postgres writes lock the row FOR UPDATE and re-read after an insert race.
