## 实现（后绿）

后端 `src/adk_agent/console.py`：

- `_scan_summary` 按 `security_report.schema.json` 严格校验：顶层只允许
  `generated_at`/`codeql`/`dependencies`/`notes`，`generated_at` 必须是非空字符串，
  `codeql`/`dependencies` 必须是对象，`open`/`vulnerabilities` 若出现必须是非负整数（拒绝布尔）；
  任何不符返回 `null`。
- 审计查询异常时 `audit.records = null`、`last_event_at = null`，并附固定码 `audit_unavailable`，
  不再把后端故障显示成空审计。
- 凭据 store 捕获 `(CredentialStoreError, ValueError)`（`UnsafePath` 是 `ValueError`），
  失败时 `keys.credentials.error = "credential_store_unavailable"`，响应 200。

前端：

- `web/src/views/SecurityView.vue`：`ops.read` 门控；四张卡（审计/密钥/策略/扫描）；
  「校验审计链」调 `GET /api/security?verify=1`；后端、校验结果与错误码均有固定文案；
  `scans` 为 null 显示「未提供扫描报告」；无 `v-html`。
- `/security` 路由与导航「安全」；`web/src/style.css` 增加 `.security-card` 等少量样式。
- 重建 `web/dist/`（`index-PSk9Bgot.js` / `index-ZqPjCqKj.css`）。

契约：`docs/contracts/console.md` 补 `audit_unavailable`、`credential_store_unavailable`
与 scans 的严格校验语义。

## 独立验证反馈修正

首轮验证判 PASS，提出 1 个 S 与 3 个 N，已全部修：

1. **S1**：含数十万层嵌套数组的扫描报告让 `json.loads` 抛 `RecursionError`，绕过 `except (OSError, ValueError)` 直冒 500。
   现捕获 `RecursionError` 并按 null 处理；新增 `test_security_treats_a_deeply_nested_report_as_missing`。
2. **N1**：`notes` 类型未校验。现在非字符串（且非 null）时报告整体按 null；新增
   `test_security_ignores_a_report_with_wrong_notes_type`。
3. **N2**：实现要求 `generated_at` 非空，比 schema 的「字符串即可」更严。把 schema 改为 `minLength: 1`
   并在契约写明「空串按 null」，实现与契约一致。
4. **N3**：审计后端不可用时点「校验审计链」，`backend_unsupported` 会覆盖 `audit_unavailable`。
   现在校验结果只更新 `verified`/`checked_records`，错误码保留 `audit_unavailable`；
   新增 `test_security_keeps_audit_unavailable_after_verify`。

## 第二轮验证反馈修正

第二轮验证判 **REJECT**：第一轮的 S1 只修了解析期，响应序列化还有一条可达 500；另外三条为契约缝隙。
全部已修：

1. **S-new-1（阻塞）**：`codeql`/`dependencies` 内 97 层以上嵌套是 schema 合法输入，原样回显时
   FastAPI 序列化抛 `PydanticSerializationError` → 500。现在只回传 `open` 与 `vulnerabilities`
   两个计数，未知字段一律不回显；新增 `test_security_drops_unknown_scan_counters`。
2. **N-new-1**：`notes: null` 被放行但 schema 拒绝。现在 `notes` 只要出现就必须是字符串。
3. **N-new-2**：原先的深层嵌套用例只用 5000 层，在 Python 3.14 上 `json.loads` 能解析，
   是假阳性。现已提高到 200000 层，并新增序列化路径的用例。
4. **N-new-3**：`generated_at` 仅空白的值与 schema 不一致。schema 增加 `pattern` `\S`，
   与实现的 `strip()` 判定对齐。

## 第三轮验证反馈修正

第三轮验证判 **REJECT**：同类 500 还能从 `generated_at` 触发。已修：

1. **S-new-2（阻塞）**：报告里的 `generated_at` 若是 JSON 转义的孤代理项（如 U+D800），能通过
   schema 与 `strip()`，但响应序列化时 `UnicodeEncodeError` → 500。现在先做 UTF-8 可编码性检查，
   失败按 `null`；新增 `test_security_rejects_a_lone_surrogate_in_generated_at`。
2. **N-new-4**：JSON Schema 2020-12 把 `1.0` 视为 integer，实现只收 `int`。现在整数
   浮点按整数接受（`1.0` → `1`），非整数浮点与布尔仍拒绝；新增
   `test_security_accepts_an_integral_float_counter`。
3. 补两条此前缺失的回归用例：`test_security_ignores_a_report_with_null_notes`、
   `test_security_ignores_a_whitespace_generated_at`。

第四轮独立验证判 **PASS**，未再提出阻塞项；核对门禁 9 步 ALL PASS、2168 passed / 105 skipped。
