notes
-----
- The success and the 500 differ only in `status`; both are one event per
  request. The transport exception records `error` and then re-raises, so the
  caller sees `ReadTimeout` and the audit still has the line.
- Every event carries the invocation trace, the peer/agent target and a hash of
  `"<method> <path>"`. The path query string is not recorded, and the tests
  assert that request bodies, response bodies, the host and query values never
  appear in the serialized event.
- `AuditTransport.aclose()` delegates to the inner transport, so wrapping a
  client does not leak the real `AsyncHTTPTransport`.
- Audit emission failures are logged and swallowed, so an audit outage cannot
  turn a working outbound call into a failure.
- Boundary: this records our side only. The remote's internal events are not
  reachable; correlation is by trace id, as `docs/contracts/a2a.md` states.
