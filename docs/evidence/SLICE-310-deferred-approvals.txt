SLICE-310 延迟审批（ADR-0049 切片 1）

日期: 2026-11-28
依据: ADR-0049 已确认；用户同意把业务可用性排在 ADK 隔离之前
范围: `core/orchestration.py`（`PlanPending`）、`orchestration/executor.py`
      （`defer_approvals`、延迟与恢复、`orchestration.deferral` 审计）、
      `orchestration/errors.py`（`ApprovalDeferred`）、`orchestration/checkpoints.py`
      （`approval_request_id`）、新增 7 条用例

一、红绿说明（如实记录）

实现前 `PlanExecutor` 没有 `defer_approvals` 参数，`PlanPending`、`ApprovalDeferred`
不存在，7 条用例必然失败（`TypeError`/`ImportError`）。本轮与实现一起落地，没有单独
抓红屏。

二、用例

    $ python -m pytest tests/test_deferred_approvals.py -q
    .......                                                          [100%]
    7 passed in 2.00s

    $ python -m pytest tests/orchestration -q
    .......s...................                                      [100%]
    69 passed, 1 skipped

    $ python -m pytest tests/test_deferred_approvals.py -q   # 含首轮修正新增的 1 条
    8 passed in 2.22s

- `test_deferred_run_returns_pending_and_creates_request`：返回 `PlanPending`，
  request id 等于 `uuid5("adk-approval:local:run-1:ticket")`，审批目录里有同一请求，
  写操作未执行，审计有 `orchestration.deferral`
- `test_approved_resume_runs_the_remaining_step`：批准后同 run_id 重跑得到
  `PlanResult`，只补跑建单步骤（`answer` 不重复）
- `test_denied_resume_raises_and_skips_the_step`：拒绝后抛 `ApprovalDenied`，写操作不发生
- `test_pending_reentry_is_stable`：未决时重复进入返回同一个 request id，不产生冲突
- `test_sync_mode_still_waits`：`defer_approvals=False` 时仍走阻塞路径
- `test_defer_requires_a_submit_capable_gate`：审批端口不能提交时报 `approval_protocol`
- `test_pending_expires_from_the_defer_ttl`：没给超时时默认 TTL 保证 `expires_at` 非空
- `test_defer_rejects_other_strategies`：`routing` 等策略在入口报错，不泄漏内部异常
- `test_approval_request_id_roundtrip`：Postgres 检查点读写保留 request id（live，无库时跳过）

三、实现中改掉的两个假设

1. 一开始用子调用的 `run_id` 生成确定 id，但执行器给每个步骤生成新的子 `run_id`，
   恢复时对不上；改为用父调用的 `run_id`（`adk-approval:<tenant>:<run>:<step>`）。
2. `ListAuditSink` 没有 `.events`，用例改用 `recent(50)`。

五、限制

- 只有库层：服务开关、resumer、通知、控制台状态在 0049-2。
- 审计 `status` 词表未加 `waiting`；延迟记 `orchestration.deferral`（status=ok）。
- 延迟模式下若审批存储不可用，提交失败按 `PlanExecutionError` 处理，不静默降级为阻塞。

六、首轮验证修正（S 级）

- **S1 内部异常泄漏**：`routing`/`fan_out`/`supervisor` 策略没有捕获
  `ApprovalDeferred`，调用方会看到内部异常。`run()` 入口加守卫：延迟模式只接受
  `single` 与 `sequential`，其余直接 `ValueError`。用例
  `test_defer_rejects_other_strategies`。
- **S2 Postgres 丢弃字段**：`PostgresCheckpointStore` 建表、SELECT、INSERT 都没有
  `approval_request_id`，加载回来永远是 `None`。已补列（含 `ADD COLUMN IF NOT EXISTS`）
  与读写，新增 live 用例 `test_approval_request_id_roundtrip`（无 `TEST_POSTGRES_URL`
  时跳过）。
- `ApprovalGate` 旁边新增 `DeferredApprovalGate` 协议，把 `submit`/`get` 写成文档契约；
  执行器仍按可等待性调用。

七、范围外

- 工具级审批令牌。
