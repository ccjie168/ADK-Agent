SLICE-194 RAG 摄取与检索的 CLI 接线
日期: 2026-11-20
依据: ADR-0035（Accepted 2026-11-20）决定 3 / slice 5 的已知缺口
基线: 2679154

一、契约（先改）

- `docs/contracts/cli.md` 新增 `adk-agent rag ingest` 与 `adk-agent rag search` 两节，写在
  「会话存储的租户 RLS」之后、「入口限流」之前：参数、退出码、输出形状、审计后端沿用
  `--audit-file|--audit-url|--audit-db`、空输入与维度不符、存储不可用的失败语义。

二、实现

- `src/adk_agent/cli.py` 新增 `rag` 子命令与 `ingest`、`search` 两段：
  - `_rag_ingest`：读正文（`--text FILE`，缺省 stdin），空文本打印 `empty text` 退出 1；构造
    `PgVectorRagStore(url, dimensions=N)` 与 `IngestionPipeline(store, EmbeddingGateway({provider:
    LiteLlmProvider(...)}, audit=sink), ...)`，调用 `ingest` 写分块，`finally` 关闭存储；成功输出
    `{"tenant","source_id","chunks"}`。
  - `_rag_search`：读查询（`--query`，缺省 stdin），`--limit` 非正退出 1，空查询打印 `empty query`
    退出 1；构造 `PgVectorRagService(..., guard=RagGuard(min_confidence=...), limit=...)`，用
    principal 的租户与 `--subject` 检索，输出 `Citation` 的 JSON 数组。
  - `_rag_embedder` 复用 `LiteLlmProvider` 与 `EmbeddingGateway`（每次调用写 `model.embed` 审计，
    预算走 `ModelPolicy.budget_usd`）；`_rag_policy` 把 `--provider` 作为允许清单。
  - `_run_rag` 把 `RagStoreUnavailable`、`ModelDenied` 与 `ValueError` 映射为退出 1 并只打印安全文案。
- 没有新增依赖、没有改动检索或写入语义、没有改 `serve-*` 路径。
- `tests/test_cli_rag.py` 十个用例，用假 store 与假 provider，不依赖 Postgres 或网络。

四、红态

基线 2679154 上 `rag` 不是合法子命令：
`pytest tests/test_cli_rag.py` → 7 failed（`SystemExit: 2`，`invalid choice: 'rag'`）；
契约用例在改契约前为红，`git show 2679154:docs/contracts/cli.md` 不含 `rag ingest`。
补 `--limit` 边界用例后单独跑：`9 passed`；再加正文文件缺失用例后 `10 passed`。

五、范围与已知缺口

- `serve-*` 与 agent 运行路径仍未调用 `RagService`，本切片只做命令行入口。
- 真实 Postgres + pgvector 与真实 LiteLLM embedding 未在本机验证（无网络凭据），属运维验收项；
  测试用假 provider 与假 store，真实 SQL 行为由 `tests/test_pgvector_store.py` 的 live 用例覆盖（需
  `TEST_POSTGRES_URL`）。
- 批量目录摄取、删除来源、重排与置信度校准不在本切片。
