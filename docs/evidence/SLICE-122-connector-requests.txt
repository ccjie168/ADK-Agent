三、行为
- 申请记录含提议的 ConnectorSpec、理由、申请人、状态与决定信息。spec.tenant 必须等于申请租户，全局连接器不能走申请。
- 状态机是 pending 到 approved 或 denied，终态不可再变。pending 不能带决定字段，approved 必须有 registered_connector。
- 文件存储 <root>/<request_id>.json，重复相同内容幂等，不同内容冲突；决定在同一把锁内只生效一次。
- Postgres 用条件 UPDATE definition->>'status' = 'pending'，并发决定只有一个赢家。
- 控制台 GET/POST /api/connector-requests 与决定路由。申请任何已认证主体可提交，租户取调用主体；决定仅 admin。
- 批准先查启用凭据绑定，再登记连接器，登记成功后才标记 approved。拒绝不碰连接器存储。
- 审计写 connector.request、connector.register 与 connector.request.decide。
- CLI connector-requests list|request|decide 支持文件与 Postgres，批准时复用连接器存储与凭据检查。
- 凭据绑定检查抽成 registry.credentials.credential_is_bound，控制台与 CLI 共用。

四、边界
- 申请无过期与清理。
- 无控制面 /v1/connector-requests。
- 批准与拒绝并发时，批准路径可能先登记连接器再遇到决定冲突；登记幂等，管理员可停用连接器。未做跨存储事务。
- CLI 决定不写审计，与现有管理命令一致。
