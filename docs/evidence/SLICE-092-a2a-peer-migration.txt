notes
-----
- The two modes ran as separate processes on separate ports, which is the
  supported way to overlap them. One process cannot serve both.
- The old shared token is rejected by the peer process, so the cutover does not
  leave a usable legacy credential behind.
- The red test run is against 6146450 because this slice verifies behavior that
  SLICE-090 added. The Library checks are unit-level (`build_a2a_app` raises
  before the optional SDK is imported), so they run without `a2a-sdk`.
- The migration guide is `docs/guides/a2a-peer-migration.md`; it uses
  placeholders only, no real tokens.
