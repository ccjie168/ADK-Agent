notes
-----
- kubectl is installed but there is no cluster: `kubectl apply --dry-run=client`
  still asks the API server for discovery and fails with connection refused.
  The gate therefore relies on `tests/test_deploy_manifests.py`, a text-level
  structural guard, and the local PyYAML parse above. PyYAML is not a project
  dependency, so the test does not import it.
- First gate run failed the secrets step: `SESSION_URL` used
  `postgresql+asyncpg://adk:replace-me@...` and detect-secrets' Basic Auth
  detector flagged the `user:password@` shape. The example Secret now omits the
  password from every placeholder and says so in a comment. Re-run is green.
- Every deployment is stateless: no `volumes`, no PVC, no `SESSION_DB`. Shared
  state is Postgres plus Redis, injected from `secretKeyRef` only. The manifest
  contains no plaintext DSN or token.
- The console and MCP deployments use 3 replicas, the audit and registry
  deployments use 2, and the console has a PodDisruptionBudget with
  `minAvailable: 2`.
- Limits are documented rather than tested: audit writes serialize per tenant
  on an advisory lock, approvals wait by polling, Redis loss degrades rate
  limiting to per-process counters, and file backends stay single-node.
- The runbook records the measured host-versus-Postgres clock skew (about 4 s)
  and repeats the NTP requirement.
