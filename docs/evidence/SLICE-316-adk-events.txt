二、用例

    $ python -m pytest tests/test_adk_events.py -q

- `test_run_event_conversion_extracts_parts`：文本、工具调用、工具结果按序提取，
  `RunEvent.text` 拼接；`to_run_event` 对平台事件幂等
- `test_run_event_drops_thought_parts`：思考片段不进平台事件
- `test_agent_runtime_consumes_platform_events`：运行时只吃 `RunEvent`，
  进度仍发 `model.text`，结果取最终文本
- `test_audit_proxy_extracts_final_text_from_run_events`：审计代理用平台事件取
  最终文本（`result_hash == hash_text("done")`），原始事件仍逐个透传
- `test_only_the_adapter_reads_adk_event_fields`：`adapters/` 与 `sandbox/` 之外
  没有 `is_final_response`、`content.parts`、`function_call` 读取

三、实现要点

- `core.RunEvent(author, final, parts)`、`core.RunPart(kind, text, name)`，
  frozen + `extra="forbid"`；`RunEvent.text` 只拼文本片段。
- `adapters/adk/events.py::to_run_event` 是唯一转换点：跳过 `thought` 片段，
  `function_call`/`function_response` 转成 `tool_call`/`tool_result`，
  平台事件原样返回。
- `runtime/execution.py` 每次收到事件先转换，再发进度、再取最终文本；
  `_emit_progress` 的入参改成 `RunEvent`。
- `runtime/audit_proxy.py` 同样转换后取最终文本，但**仍然逐条透传原始事件**，
  MCP 的 `_run_agent` 与 A2A 执行器依赖原始事件。
- `docs/contracts/run_event.schema.json` 由 `scripts/export_contracts.py` 生成。

六、首轮验证修正

首轮 PASS，按 N2 收紧：兼容演练的 `events` 一项现在要求
`Event.is_final_response` 仍是普通方法（`inspect.isfunction`）。如果 ADK 把它改成
property 或改名，`to_run_event` 会回落到不存在的 `Event.final`，所有事件都被判成非
最终事件、结果文本与 `result_hash` 变成空串且不报错；这条检查让升级时先红。

其余 N 项记录不修：源码扫描用正则，`get_function_calls()`、`getattr(content, "parts")`
这类改写会漏检（当前树干净）；扫描暂时排除整个 `adapters/`，目前只有 `adapters/adk`；
`RunPart` 不含 `part.text/thought` 之外的字段，截图/文件类内容要用时再扩。

七、限制

- `sandbox/` 仍读 ADK 事件与模型类型（manifest 侧、worker 侧），0046-3 迁；
  扫描用例暂时排除该目录，证据如实记录。
- 转换只覆盖平台用到的字段（author、final、文本、工具名）；ADK 事件里更大的
  `content`（图片、文件引用）不进平台类型，未来要用时在适配层扩展。
- `RunEvent` 不进任何 HTTP 载荷，schema 只是边界文档；控制台 SSE 仍发
  `ProgressEvent`。
