SLICE-142 控制面凭据写入端点
日期: 2026-11-18
依据: ADR-0025 第 7 条
基线: d23c6a4

一、实现

- `build_registry_service_app` 新增 `credentials` 与 `key_backend`；新增
  `POST /v1/credentials` 与 `POST /v1/credentials/{credential_id}/disable`。
- 明文 `secret` 由服务端用当前 KEK 信封加密后只存密文；响应与审计都不含明文或密文。
  审计 `agent_ref.version` 是 `credential.<key id>`，`target` 是 `<tenant>/<credential_id>`。
- 请求体只接受 `tenant`、`credential_id`、`secret_ref`、`description`、`secret`；
  `wrapped_secret` 等其他字段 400 `invalid_credential`；明文必须单行、非空、最长 8192。
- `serve-registry` 新增 `--credentials-dir`/`--credential-db`/`$CREDENTIAL_DATABASE_URL` 与
  `ADK_SECRET_KEKS` 接线；keyring 非法时退出 1 并提示；Postgres 凭据池在 uvicorn 退出后
  best-effort 关闭。
- 静态 token 模式没有调用方租户，`disable` 必须显式给 `tenant`，否则 400 `invalid_request`。

三、红态

基线没有两个端点（404）与 `--credentials-dir`（argparse 未知参数）；新增用例在基线上失败。

四、范围与已知缺口

- 明文经网络到达控制面，需在非回环部署上走 TLS；本切片不做 TLS 终止，属于部署要求。
- 轮换命令与 `KeyBackend.rewrap()` 留给下一片（会话中已确认给端口加 `rewrap()`）。
- `credential.decrypt_failed` 审计仍随轮换切片一起做。
- 控制台凭据面板仍只登记元数据，没有明文写入表单。

五、第一轮独立验证

结论 DO NOT MERGE。安全核心通过（无明文泄露、无越权、无法写入客户端密文），但契约与实现不符、
停用路由对坏输入 500。处理：

1. 中：契约写“同名同定义重发返回 200”，实现只会 201/409；`_definition` 含 `created_at`。
   契约改为“同 id 已存在返回 409”，并同步修正 `credentials register` 的 CLI 契约。
2. 中：纯空白明文被接受。加密前要求 `secret.strip()` 非空，补用例。
3. 中：`disable` 对空 `tenant`、含不安全字符的 id/tenant 抛未捕获异常返回 500。
   路由在构造 actor 与访问存储前按 `^[A-Za-z0-9][A-Za-z0-9._+-]*$` 校验，返回 400 `invalid_request`，补用例。
4. 低：spec 写“日志只记异常类型”，加密失败路径实际用 `logger.exception`。加密失败改为只记类型名，
   spec 措辞与实现一致。
5. 低：非 Postgres 的 `--credential-db` 抛 traceback。`serve-registry` 捕获 `CredentialStoreError`，
   打印 `invalid credential store` 并退出 1，补用例。
6. 低：契约里凭据端点的 `tenant_forbidden` 不可达（非 admin 先得 403）。契约改为“admin 可写任意租户”。

保留为已知缺口（不在本切片）：

- 控制台 `/api/credentials` 仍接受请求体里的 `wrapped_secret` 等字段（存量行为），与 `/v1/credentials`
  的“不接收客户端密文”不同；后续把控制台收口或记录为正式风险。
- admin 跨租户写入的审计落在调用方租户链，不在目标租户链（与结账台存量行为一致）。
- Postgres 下并发停用可能重复写 `credential.disable`。
- 停止后的 Postgres 凭据池关闭是 best-effort。
