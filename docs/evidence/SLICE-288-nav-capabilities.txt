## 反例（先红）

新增 `tests/test_console_vue_nav_capabilities.py` 后，把 `web/src/App.vue` 临时替换成 master 版本：

    python -m pytest tests/test_console_vue_nav_capabilities.py tests/test_console_vue_shell.py \
        tests/test_console_vue_wizard.py tests/test_console_vue_ecosystem.py tests/test_console_vue_roles.py -q

失败项：master 的侧栏入口没有任何 `v-if` 能力门控。
恢复实现后连同相关的既有导航/外壳测试：

    python -m pytest tests/test_console_vue_nav_capabilities.py tests/test_console_vue_shell.py \
        tests/test_console_vue_wizard.py tests/test_console_vue_ecosystem.py tests/test_console_vue_roles.py -q
    37 passed

## 实现（后绿）

`web/src/App.vue`：

- 每个 `router-link` 入口加 `v-if="auth.hasCapability('<cap>')"`（映射见 spec）；
  生态入口是三个读取能力的或；设置入口不设门控。
- 四个分组按组内任一能力加 `v-if`，全组不可见时整组隐藏。
- 保留原有 `to="/..."` 标记，既有导航断言无需修改。

`docs/contracts/console.md` 的前端壳一节补一句「侧栏入口按能力过滤，不参与授权」。

## 独立验证反馈修正

首轮独立验证判 **REJECT**（B1 + 1 S + 3 N），已处理：

1. **B1**：「治理」组级 `v-if` 漏了 `audit.read`，只有 `audit.read` 的自定义角色会看到 /audit 入口被整组隐藏。
   组条件补上 `auth.hasCapability('audit.read')`；组级测试改为逐个断言组条件覆盖组内全部子能力
   （`test_nav_groups_cover_every_child_capability`），这类漏项会被抓到。
2. **S1**：证据的门禁段补齐 `--fast`/`--full` 的真实数字。
3. **N1**：向导入口按视图一致接受 `registry.publish` 或 `registry.compose`
   （compose-only 进入后由视图说明不能发布）；新增 `test_wizard_entry_accepts_publish_or_compose`。
4. **N2**：`console.md` 的「能力清单获取失败保持现有布局」改为「按空能力渲染，只保留无能力约束入口」。
5. **N3**：组级测试改为覆盖组内全部子能力，不再只看 label 前是否有 `v-if`。

第二轮复验 REJECT 了同类遗漏与测试盲区，已处理：

6. **B2**：「开发」组级条件漏了 `registry.compose`，只有 compose 的自定义角色会被整组隐藏。
   组条件补上；向导入口与视图一致接受 publish 或 compose。
7. **N4**：组级测试改为从每个分组的子入口门控**推导**所需能力（不再手写字典），
   实测把 `registry.compose` 从组条件删掉会让该用例变红。
8. **N5（记录并修）**：Agent 中心的「新建 Agent」按钮原先只按 `registry.publish`，与侧栏入口
   （publish 或 compose）不一致；现在同样接受两者，compose-only 进入向导后由视图说明不能发布。
