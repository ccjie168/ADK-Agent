三、行为
- 绑定记录只有元数据。引用必须是 secret://<tenant>/<name>，租户段与记录租户不一致时模型拒绝。
- 环境变量映射为 ADK_SECRET_<TENANT>_<NAME>，大写，非字母数字转下划线。
- 单段 secret://name 仍走全局 PrefixedEnvSecretProvider，语义不变。
- 文件存储按 <root>/<tenant>/<id>.json 落盘，重复相同内容幂等，不同内容冲突，停用幂等。
- Postgres 存储键 (tenant, credential_id)，与文件语义一致。
- 控制台提供 GET /api/credentials、POST /api/credentials、POST /api/credentials/{id}/disable，写操作仅 admin，读按租户过滤，登记与停用写审计。
- 停用可带 ?tenant= 定位其他租户，管理员可管理同 id 的多个租户绑定。
- CLI 提供 credentials list|register|disable，后端为 --credentials-dir 或 --credential-db，未显式给出时读 CREDENTIAL_DATABASE_URL。
- 配置了凭据存储时，连接器登记要求两段引用有同租户启用绑定；全局连接器不得使用两段引用，否则 400 credential_unbound。
- 工具网关按 --connector-tenant 包装租户作用域提供者，跨租户引用取用时按 secret_unavailable 拒绝。

四、边界
- 不存密钥值。密钥后端、KMS 与轮换留给单独 ADR。
- 控制面 /v1/credentials 未做，跨副本通过共享 Postgres 表 adk_credentials 实现。
- 工具网关只做租户作用域，不检查绑定是否存在；绑定存在性在连接器登记处检查。
- 连接器自助申请与审批流是下一步切片。

五、CodeQL 与密钥扫描
- PR #29 首次扫描新增 11 条：8 条 py/path-injection 在 registry/credentials.py，3 条 py/log-injection 在 console.py 新路由。
- path-injection 与 ADR-0022 的 25 条同一模式，路径段先过 _NAME 全匹配再拼路径；按误报 dismiss。
- log-injection 记的是已校验标识符，且 SLICE-120 的中央清洗器转义 CR/LF；按误报 dismiss。
- 复核后开放告警 0。
- 契约示例里的 secret_ref 赋值在 CI 的 Python 3.13 依赖集下被 detect-secrets 判为 Secret Keyword。示例是占位符，已按已审误报写入 .secrets.baseline，没有写入真实值。
