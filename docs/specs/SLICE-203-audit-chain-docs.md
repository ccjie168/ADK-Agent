# SLICE-203 审计链校验的运维说明

状态: gated
依据: ADR-0037（Accepted 2026-11-21）切片 3。

## 意图

1. 运维手册的「值守检查」写清 `verify-audit` 校验的是**存储内容**：只要存储内容能被当前规范形式
   复现，升级新增审计字段就不会断链，历史记录（包括 SLICE-188 之前的）按原样通过；已经不一致的
   记录（如历史 `-0.0` 行）不会因升级恢复，仍按断链调查。
2. 说明断链报告的含义：序号、租户，「升级后突然全部通过」不是规则放松，断链表示存储内容与记录
   `hash` 对不上（常见原因是存储被改或记录损坏，升级切换校验器也可能暴露既有不一致）。
3. 指向 `docs/contracts/audit_chain.md` 的哈希口径。

## 5 问威胁建模

1. **数据**：运维对审计链校验的理解与处置流程。
2. **调用方**：值守与发布人员。
3. **信任边界**：文档 → 运维判断。
4. **恶意输入最坏结果**：把断链误判为正常升级现象而忽略真实篡改。缓解：写明断链只在存储内容能被
   规范形式复现时才会因升级消解，已不一致的记录仍要按断链调查，并给出定位方式。
5. **失败是否泄露信息**：无代码变更。
