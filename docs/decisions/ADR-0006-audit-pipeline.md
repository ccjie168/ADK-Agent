# ADR-0006 审计管线独立部署并做租户哈希链

状态: Accepted   日期: 2026-11-12   批准: Jie CAO（会话确认）

## 背景

ADR-0002 第 6 条要求审计是追加事件流，按 tenant 和日期做哈希链，提供篡改检测。第 9 条把审计管线放在最后拆。

现状：审计写进程内存或 JSONL 文件，没有链，没有跨进程汇聚。多个网关进程各自写各自的文件，无法统一校验。

## 决定

1. 审计管线独立成服务。`POST /v1/events` 接收 `AuditEvent`，返回 202 和记录哈希。
2. 存储记录是 `AuditRecord` = event + prev_hash + hash。哈希是租户链上一条记录，`sha256(prev_hash + canonical(event))`。
3. 每个租户一条链。服务启动时读文件重建每个租户的最后一条哈希。
4. 服务写 JSONL 并 fsync 后才返回 202。写入失败返回 502，调用方的 `HttpAuditSink` 抛 `AuditSinkUnavailable`。
5. 校验命令 `adk-agent verify-audit FILE` 逐条重算。任何断链退出 1。
6. 提供方沿用 ADR-0004 的鉴权规则：只有 `/healthz` 开放，非回环无 token 拒绝启动。
7. 这一版不带日期分区、轮转、集中存储和投递重试。规模上来后换后端。

## 后果

- 多个网关可以指向同一个审计服务，得到一条可校验的链。
- 审计服务不可用时调用方看到错误。是否阻塞业务由装配决定，默认不吞错。
- JSONL 是单进程追加，多副本写同一文件不安全。生产要么单写者，要么换 Postgres。
- 没有签名，链只能证明内部一致，不能证明来源。
