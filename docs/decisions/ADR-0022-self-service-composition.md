# ADR-0022 自助 agent 组合、自动化与角色视图边界

状态: Accepted   日期: 2026-11-15   签字: Jie CAO（会话确认）

## 背景

平台已有治理内核：签名工件、市场按 pinned 版本加载、生命周期、工具授权、审批、审计链、租户 RLS 与跨副本部署。四类角色分别是平台管理员、Agent 开发者或发布者、运营或审批人、终端用户。

现状有三个缺口，方向需要一次定清。

- 控制台把全部面板展示给所有登录用户。服务端已经按 `admin` 与租户拦截，但前端不读取角色，越权操作在点击后才收到 403。
- 工具对接已有连接器注册、出站白名单、`secret://`、健康检查与审计，缺租户自助绑定凭据与按用户授权。
- agent 配置是代码优先。`publish` 接受签名工件，市场按 pinned 版本加载，评测门禁生效。没有可视化组合，也没有调度或事件触发。

关键约束来自执行模型。`registry/loader.py` 直接在进程内 `exec` 已签名工件。`sandbox/` 的进程隔离、`RLIMIT` 与出站控制只服务工具源，不覆盖 agent 工件。让业务用户提交代码，等于在平台身份下运行未隔离的代码。

不决定的代价是两种可预期的错误。要么在控制台里散落角色判断，与后端授权漂移。要么先做构建器，把任意代码执行当成配置问题。

## 决定

1. **一个控制台，能力驱动视图。** 新增服务端能力清单接口，返回主体、租户、角色与 capabilities。角色到能力的映射只在服务端一处定义。前端按 capability 隐藏或禁用导航与按钮，不写角色名分支。每个既有服务端检查保留，界面隐藏不构成授权。角色继续来自 token 或启动参数。
2. **平台部署操作留在 CLI 与运维手册。** 控制台最多增加只读状态页，例如副本健康、审计链状态、待办审批。RLS 启用、备份恢复、部署、工件与审计签名密钥轮换不提供网页写操作。
3. **自助配置只做声明式组合。** 用户选择受控模板、填写参数、声明所需工具授权。平台生成 manifest，用平台侧发布密钥构建并签名工件，再走既有评测门禁与审批。用户不提交 Python、脚本或任意文件。
4. **租户自带代码在 agent 级沙箱落地前不做。** 未来需要单独 ADR 定义隔离方式、资源上限、出站策略与运行身份。工具沙箱不能直接复用为 agent 沙箱。
5. **工具对接自助化分两步。** 凭据只以 `secret://` 引用绑定，租户凭据存储需要单独的密钥后端设计。连接器注册仍由管理员批准。用户申请工具授权复用现有 `ToolGrantRequest` 流程，不允许在界面或 manifest 内联凭据。
6. **自动化是独立服务，不是控制台按钮。** 首期只做定时与 webhook 触发。触发只调用已发布、pinned 且声明了工具授权的 agent。每次触发按租户计配额、写审计、对副作用走审批，并具备重试与幂等语义。触发器不允许内联脚本。
7. **组合结果就是普通已发布版本。** 版本按 digest 固定，评测门禁、生命周期与市场规则原样适用。不提供热替换或绕过发布的快捷路径。
8. **能力清单的初始映射。** 能力名稳定，角色映射可调整。
   - 终端用户：`chat.run`、`runs.read`、`sessions.read`。
   - 运营或审批人：上述加 `approvals.read`、`approvals.decide`、`grants.read`、`grants.decide`、`audit.read`、`connectors.read`、`peers.read`、`registry.read`。
   - Agent 开发者或发布者：`registry.read`、`registry.publish`、`eval.read`、`tools.read`、`lifecycle.read`。
   - 平台管理员：全部能力，另有 `policy.write` 与 `ops.status`。
   - `admin` 角色继续隐含全部能力，与现有服务端判断一致。

## 备选与否决

- **每个角色一套 UI**：四套前端，授权规则会漂移；否决。
- **把部署与密钥轮换搬进网页**：爆炸半径大，网页持有高价值凭据；否决。
- **直接做任意代码构建器**：当前 loader 在进程内执行，等同于远程代码执行；否决。
- **复用工具沙箱隔离 agent**：作用对象与威胁模型不同，资源与网络策略也不一样；否决。
- **接入外部工作流引擎作为首期方案**：新增依赖与运行模型，先自建最小调度；暂缓。
- **在界面内联凭据**：与密钥禁区冲突；否决。

## 后果

- 角色视图是一个小切片，风险集中在能力映射与前端隐藏逻辑，服务端授权不变。
- 平台发布密钥成为新的高价值资产。工件签名密钥的托管、轮换与审计需要单独立项，现有审计密钥环只覆盖审计记录。
- 声明式模板限制了表达力。无法用模板表达的需求回到代码优先发布，由开发者签名。
- 自动化引入调度状态、时钟偏差与重试语义，需要新的运行手册与失败模式说明。
- 没有租户开通与角色管理接口时，能力清单只能反映身份提供方给出的角色。站内角色分配属于控制面能力，另立 ADR。
- 沙箱落地前，终端用户的参与边界停在选模板、填参数与申请授权。
