ADK Agent · 当前阶段说明4 / 18
一次调用的全过程

从身份到审计，每一步都有落点

1 身份OIDC 或 Bearer 解析成 Principal，带 tenant、subject、roles。
2 策略RBAC 拒绝优先；工具查长期授权与临时授权；连接器查 egress 白名单。
3 模型模型网关校验 provider，记录 token 与成本，provider 故障时熔断。
4 工具工具网关执行，沙箱限制资源与网络，连接器用 secret:// 解析凭据。
5 留痕agent.run、model.call、tool.call、a2a.call 写入租户哈希链并逐条 HMAC。
6 计量每租户配额与并发租约，入口限流，跨副本计数走 Redis。

被拒绝时

越权工具返回拒绝并留痕；审批未通过不执行；限流返回 429；配额不足直接拒绝。

出问题时

按 trace id 串起控制台、MCP、模型与工具事件；审计链可整链验证，失败按租户与序号定位。

从开发到上线

一条主流程，八个可检查的节点

1 new脚手架生成 agent 项目与 manifest。
2 validate校验 manifest，拒绝未知字段与缺字段。

7 image推到镜像仓库，取 digest，写进部署清单。
8 load按引用或市场页加载，验签、校验 digest、检查生命周期。

发布门禁

评测失败、生命周期退役、digest 不匹配、验签失败，都会挡住加载或启动。

灰度

按权重路由到不同版本，出现问题时回到上一个 digest。

留痕

发布、加载、退役都写审计；谁在什么时候发布了什么，可以回查。

  • #tab 直达面板，深色主题记住选择
  • 窄屏改为顶部换行导航，无横向溢出
1 登录浏览器跳转 IdP，带 code_challenge 与 state。
2 回调控制台用 code 与 verifier 换 token，secret 不出服务端。

容易混淆的两个 registry

Agent 注册表不是镜像仓库

Agent 注册表（平台内置）

存 agent 的版本、manifest、工件字节、评测报告、生命周期、连接器、peer 与远端目录。由 adk-registry、文件或 Postgres 提供，按租户鉴权。控制台、MCP 和 publish 都读它。

镜像仓库（OCI Registry）

存容器镜像。开发阶段用 registry:2，未来换 Harbor。Kubernetes 按 image@sha256:digest 拉取，tag 只用于人看。发布 workflow 负责推送并输出 digest。

对比项Agent 注册表镜像仓库
存什么agent 版本、工件、评测报告、生命周期容器镜像层与 manifest
谁在用控制台、MCP、publish、评测Kubernetes、Docker、发布 workflow
鉴权平台 Principal 与租户绑定registry 账号或 Harbor 机器人账号
当前状态文件与 Postgres 双后端，可独立服务化本地 registry:2 已跑通，Harbor 待装

两者都用 digest 保证不可变，但用途不同。上线时先发布 agent 工件，再构建并推送镜像，最后把镜像 digest 写进部署清单。

ADK Agent · 当前阶段说明10 / 18
租户、身份与权限

租户是边界，权限默认拒绝

OIDC

控制台支持浏览器授权码加 PKCE 登录，三个服务都能接 OIDC。token 解析出租户与角色，共享 Bearer 只建议内网演示。

RBAC

租户角色绑定，拒绝优先。聊天、工具、计划、审批各走各的策略检查。

RLS

sessions、events、user_states、app_states 四张表由 Postgres 行级安全强制，租户取自已认证 principal。

配额

每租户运行次数与并发租约，存 Postgres，跨副本共享，表上带 RLS。

临时授权

工具授权走申请、审批、到期与用量视图，运行时把长期授权和临时授权合并，任一允许即可。

A2A peer

提供方按 peer 身份认证，按 read 与 invoke 授权，审计身份随 peer，和共享 token 模式互斥。

生产连接必须用表属主角色，不能是 superuser 或带 BYPASSRLS，否则 RLS 会被绕过。开启前先建表，再用 sessions enable-rls 安装策略。

ADK Agent · 当前阶段说明11 / 18
审计与审批

能证明发生过什么，也能拦住不该发生的

审计链

  • 覆盖 agent.run、model.call、tool.call、a2a.call、策略与审批事件
  • 每租户一条哈希链，逐条 HMAC 签名，记录带 kid
  • 按记录数分段，跨段可校验，密钥可轮换而不作废旧记录
  • 文件、HTTP、Postgres 三种落点，多副本共享同一份审计
  • verify-audit 整链验证，失败按租户与序号定位
  • 按租户查询 API，控制台审计面板读同一份数据

人工审批

  • 高风险工具与计划可以要求人工批准
  • 收件箱支持跨进程、跨副本，条件 UPDATE 保证并发决策只生效一次
  • 过期用数据库 now() 判断，到期后从待办消失，执行器收到超时
  • 归档与删除用 approvals prune，审批表在备份范围内
  • 控制台与 CLI 都能申请、审批、查看用量与到期

审计与审批表当前不做 RLS，按服务层过滤，admin 才能跨租户。这是 ADR 里写明的后续加固项。

下一步

五个可执行的动作

  1. 试点上线：选一个团队和 2 到 3 个 agent，开 OIDC、配额、审批与日验。验收：两周审计全过，回滚一次。
  2. 装 Harbor：WSL2 内安装，端口改 8089 与 8443，建 adk 项目与机器人账号。验收：release workflow 推送成功并输出 digest。
  3. 首次真实发布：在 master 手动触发 release，取 digest 回写清单并合并。验收：集群按 digest 拉起新版本。
  4. 日志脱敏：单独切片，批准后修改日志断言。验收：日志与指标不出现 token、DSN 与待审输入。
  5. 审计与审批 RLS：评估 admin 跨租户查询的上下文切换，给出 ADR。验收：非 admin 跨租户读为零行。

顺序建议：先试点，再 Harbor 与首次发布，然后补日志脱敏，最后做审计与审批 RLS。
