# v0.1.0（2026-11-18）

首个可用版本。范围是 M0 到 M5 与 SLICE-036 到 SLICE-144；安装与使用见
`docs/guides/install-and-use.md`，多副本运维见 `docs/guides/operations.md`。

## 包含内容

- **框架与运行时**：`core` 端口、模型网关（允许列表、熔断、限流）、工具网关（guard、沙箱、
  连接器）、租户配额（文件与 Postgres、RLS）、审批（文件与 Postgres、TTL、归档）。
- **入口**：MCP（stdio 与 streamable-http、OIDC、审计、配额）、A2A（对端身份、授权、出站审计）、
  控制台（聊天、运行/计划/轨迹、审批、注册表、工具、授权、连接器与申请、凭据、对端与远程目录）。
- **注册表与工件**：文件与 Postgres 注册表、控制面服务、内容寻址工件存储、Ed25519 发布签名、
  可信公钥、生命周期、评测报告、声明式组合器、构建密钥与 `in_process` 门槛。
- **执行层级与沙箱**：manifest 的 `execution_tier`、子进程 agent sandbox（RLIMIT、网络/进程守卫、
  模型出口中介、工具调用经父进程与工具网关）、发布默认 `sandboxed`。
- **触发**：webhook 与 schedule，幂等 key、单赢家调度、执行审计与配额。
- **租户凭据**：只存引用的绑定、本地 KEK 信封加密（AAD 绑定租户与凭据 id）、运行时解析
  （工具网关、控制台远程 agent、`remote-agents` CLI）、控制面 admin 写入端点、数据密钥重包裹轮换。
- **治理**：每租户审计哈希链（文件与 Postgres、分段、签名与 keyring）、限流（内存与 Redis）、
  OIDC、日志注入过滤、备份恢复、K8s 多副本清单。
- **文档**：安装与使用手册、运维手册、A2A 对端迁移、安全评审、每切片 spec 与证据。

## 安装

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev,litellm,claude,publish]"
.venv/Scripts/python.exe scripts/check.py --fast
```

模型、MCP、控制台、发布、凭据与 Docker 的完整步骤见 `docs/guides/install-and-use.md`。

## 升级说明

- 这是首个版本，没有从更早版本升级的路径。
- 凭据：引用首段必须等于记录租户，旧的 `secret://<peer>/<name>` 写法要改成记录租户后重新注册。
  打 tag 前的内部记录如果 `credential_id`/`tenant` 超过 128 字符，没有改名命令，需要停用后按新 id
  重新注册；这只影响内部记录，不影响全新安装。
- 轮换：把新 KEK 加入 `ADK_SECRET_KEKS` 并把 `active` 指向它，保留旧 key，再跑
  `credentials rewrap --tenant T`。删除旧 key 前确认所有带密文记录的 `secret_key_id` 都是新 key id；
  没有密文的回退记录计入 `skipped`，不需要重包裹。
- `publish` 带工件时只支持 `in_process`，并且需要构建密钥与构建公钥信任文件；
  沙箱工件的发布等后续切片开放。

## 已知缺口

- KMS/Vault 尚未接入；`KeyBackend` 端口已预留，当前只有本地 KEK。
- 控制台凭据面板仍只登记元数据，没有明文写入表单；明文值可经控制面 `/v1/credentials` 或
  CLI `credentials register --secret-stdin` 写入，服务端/CLI 加密后只存密文。
- ADR-0025 第 8 条的 `credential.decrypt_failed` 审计尚未实现。
- 构建签名只绑定工件 digest，不绑定发布记录 manifest；HTTP 注册表发布仍可在 upload 处补齐比较。
- admin 跨租户写凭据的审计落在调用方租户链，不在目标租户链；Postgres 下并发停用可能重复审计。
- `scripts/demo_seed.py` 在本地演示信任域内仍生成只带演示发布签名、没有平台构建签名的 `in_process` 工件。
- 文件凭据存储的 Windows 文件锁对永久错误没有重试上限；只读目录上停用记录会失败。
- 沙箱的残余风险：RLIMIT_NPROC 按 uid 计数、POSIX 网络守卫是 Python 层、Windows 只有脚本级守卫
  （具体见 `docs/contracts/sandbox.md`；总体取舍见 ADR-0024 第 9 条）。
